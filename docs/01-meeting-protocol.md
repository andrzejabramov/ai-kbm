## 💬 Ход обсуждения

### Блок 1. Текущее состояние и проблемы (Нагорный П.В.)

🟢 **Факт:** Предприятие ООО «КБМ» производит буровые наконечники. Основная учётная система — 1С:Управление нашей фирмой (1С:УНФ, типовая ред. 3.0, платформа 8.3.24).
🔴 **Проблема:** Персонал производственных цехов саботирует работу в 1С («сложный интерфейс», «нет времени»). Документы дублируются в Excel и на бумаге. Данные в 1С неактуальны.
🟡 **Требует уточнения:** Насколько глубоко настроена 1С:УНФ?

> _Ответ адм. 1С:_ Конфигурация типовая, есть небольшие доработки (печатные формы для ОТК, отчёт «Выработка по нарядам»). HTTP-сервисы ранее не публиковались.
> 🔴 **Риск:** Настройка HTTP-сервисов 1С займёт дополнительное время. Включено в Этап 9 плана внедрения.

### Блок 2. Операционные боли и альтернативные сценарии (по ролям)

_(Детализация для исключения неоднозначностей и обработки граничных случаев)_

#### Мастер цеха

- **Основной сценарий:** Голосовой или текстовый ввод «Сдал 50 шт. НБ-150 в ОТК» → AI создаёт черновик документа.
- **Альтернативный сценарий (A1):** AI не распознал номенклатуру (уверенность < 80%). Система задаёт уточняющий вопрос: «Вы имели в виду "НБ-150" или "КБ-50"?».
- **Ошибочный сценарий (E1):** Тайм-аут ответа HTTP-сервиса 1С (> 5 сек). Система сообщает: «1С временно недоступна, черновик сохранён локально и будет отправлен при восстановлении связи».

#### Снабженец / Кладовщик

- **Основной сценарий:** Запрос «Что нужно заказать до конца недели?» → AI формирует черновик «Заказа поставщику» на основе остатков и спецификаций.
- **Ошибочный сценарий (E2):** Попытка провести «Расход» раньше «Прихода» (риск «минуса на складе»). AI блокирует действие и выдаёт предупреждение: «Недостаточно остатков. Сначала оформите поступление».

#### Контролёр ОТК / Бухгалтер

- **Основной сценарий:** AI автоматически подтягивает данные из чата для создания «Акта контроля качества» или сверки нарядов.
- **Ошибочный сценарий (E3):** Дублирующийся запрос от пользователя (защита от двойного создания документа). Система проверяет хэш запроса и блокирует дубликат в течение 60 секунд.

#### Администратор 1С

- **Опасение:** «AI-агенты будут создавать документы напрямую? А если ошибутся?»
- **Решение (зафиксировано):** Все документы создаются строго как **черновики**. Проведение в 1С возможно только после явного подтверждения пользователем (двойное подтверждение для сумм > 100 000 ₽).

### Блок 3. Технические требования, статусы и безопасность

🟢 **Стек:** FastAPI + Qwen (через OpenRouter API для MVP, прямой API в продакшене) + ChromaDB (векторная БД) + HTTP-интеграция с 1С:УНФ.
🟢 **Развёртывание:** Docker-контейнеры на существующей ВМ Заказчика (Ubuntu 22.04, 6 vCPU, 11 GB RAM).

#### Статусы сущностей и правила переходов (для Доп. соглашения №1)

| Сущность          | Статусы                                                     | Правило перехода                                                                          |
| :---------------- | :---------------------------------------------------------- | :---------------------------------------------------------------------------------------- |
| **AI-Сессия**     | `Active`, `Escalated_to_Human`, `Closed`                    | При 2 нераспознанных запросах подряд → `Escalated_to_Human` (создание тикета для админа). |
| **Документ в 1С** | `Draft_AI`, `Validated_by_User`, `Posted_to_1C`, `Rejected` | Запрещён прямой переход `Draft_AI` → `Posted_to_1C`. Требуется валидация пользователем.   |

#### Требования к безопасности и ролям

1. **RLS (Record Level Security):** AI-агент выполняет действия в 1С строго в рамках прав авторизованного пользователя (мастер не может провести документ бухгалтера).
2. **Аудит:** Полный лог всех действий AI (кто, что спросил, какой черновик создан, время ответа). Срок хранения: 1 год.
3. **Секреты:** API-ключи LLM и доступы к 1С хранятся только в Docker Secrets / `.env`. Запрещено хранение в коде.

### Блок 4. Измеримые функциональные ожидания и SLA

_(Устранение неоднозначностей для приемки работ)_

| Параметр                          | Метрика / Значение                 | Пояснение                                                                                                   |
| :-------------------------------- | :--------------------------------- | :---------------------------------------------------------------------------------------------------------- |
| **Время ответа AI (p95)**         | ≤ 5 секунд                         | При стабильном интернет-соединении и доступности LLM API.                                                   |
| **Точность извлечения сущностей** | ≥ 95%                              | Для структурированных данных (сумма, дата, номенклатура). При расхождении > 5% — запрос уточнения.          |
| **Доступность системы**           | 99.5% в рабочие часы (08:00–18:00) | Плановые работы 1С не учитываются.                                                                          |
| **SLA эскалации**                 | ≤ 15 минут                         | Если AI не может обработать запрос, он передаётся ответственному сотруднику с высоким приоритетом.          |
| **Офлайн-режим (деградация)**     | Частичная доступность              | При недоступности 1С AI работает только в режиме «Вопрос-ответ по базе знаний» с уведомлением пользователя. |

🟢 **Платежные ограничения:** Все внешние сервисные оплаты (при необходимости расширения функционала) проходят исключительно через **ЮKassa, СБП или карты «Мир»**.

🔴 **Ключевые риски и митигация:**

1. **Саботаж персонала:** Поэтапное внедрение, выбор «чемпионов» среди сотрудников, демонстрация сокращения времени операции с 15 мин до 2 мин.
2. **Галлюцинации LLM:** Строгие системные промпты, RAG с проверкой контекста, запрет на генерацию данных «из головы», режим черновиков.
3. **Рост расхода токенов:** Кэширование частых запросов через ChromaDB, лимитирование запросов на пользователя в день.
