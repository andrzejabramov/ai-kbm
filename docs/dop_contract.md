## 3. ДОПОЛНИТЬ ДОГОВОР ПРИЛОЖЕНИЕМ № 4

Дополнить Договор **Приложением № 4** «Статусы сущностей, целевые метрики (SLA) и принципы работы ИИ‑агентов» следующего содержания:

**4.1. Статусы документа в приложении:** Draft_AI (черновик создан AI) → Validated_by_User (подтверждён пользователем; для сумм > 100 000 ₽ — после двойного подтверждения) → Posted (проведён в собственной БД) → Synced_to_1C (для объектов интеграционного контура) → Archived; Draft_AI → Rejected → Draft_AI (повторная генерация). **Запрещён прямой переход Draft_AI → Posted.**  
**4.2. Статусы AI‑сессии:** Active; Escalated_to_Human (2 нераспознанных запроса подряд, SLA эскалации ≤ 15 мин); Closed.  
**4.3. Статусы передачи в ОТК:** Pending_QC → QC_Approved → Archived; Pending_QC → QC_Rejected → Rework → Pending_QC.  
**4.4. Целевые метрики (SLA):** время ответа AI p95 ≤ 5 с; точность извлечения сущностей ≥ 95% (расхождение > 5% → уточнение); доступность 99,5% в рабочие часы 08:00–18:00; время создания черновика ≤ 10 с; интеграция с 1С ≤ 30 с; уведомление об ошибке ≤ 5 с; деградация при недоступности 1С — режим «вопрос‑ответ по базе знаний» с уведомлением пользователя.  
**4.5. Принципы работы ИИ‑агентов:** все документы — черновики Draft_AI, проведение только после подтверждения пользователем; подсветка полей с confidence < 80%; RAG‑поиск только по векторной базе знаний (ChromaDB); запрет ответов «из головы»; двойное подтверждение сумм > 100 000 ₽; RLS — действия AI строго в правах авторизованного пользователя; полный аудит действий AI, срок хранения журнала 1 год; секреты (API‑ключи, доступы) — только Docker Secrets/.env; защита от дублирующих запросов (хэш‑проверка, блокировка 60 с).  
**4.6. Резервное копирование:** ночные бэкапы PostgreSQL; RPO ≤ 24 ч; RTO ≤ 4 ч.

## 4. ФИКСАЦИЯ СОГЛАСОВАННЫХ РЕШЕНИЙ (закрытие открытых вопросов)

**4.1. (O‑1 / Y‑01)** LLM‑провайдер: MVP — Qwen через OpenRouter API; продакшен — прямой API Qwen. Изменение провайдера — решением Исполнителя в пределах ориентировочного бюджета (п. 5.11 Договора в ред. п. 1.3 Соглашения) с уведомлением Заказчика.  
**4.2. (O‑2 / Y‑02)** Telegram в MVP не входит; интерфейс MVP — адаптивный веб‑чат. Telegram‑бот — последующие этапы по Заказу.  
**4.3. (O‑3 / Y‑03)** Миграция исторических данных из Excel до старта MVP **не выполняется**. Заказчик передаёт справочные данные (номенклатура, спецификации, прайсы) в электронном виде; Исполнитель выполняет структурирование и векторизацию на этапе 2.  
**4.4. (O‑4 / Y‑04)** Отдельная веб‑админ‑панель в MVP не входит; журнал действий AI предоставляется Администратору 1С средствами аудита (п. 4.5 Приложения № 4). Админ‑панель — последующие этапы по Заказу.  
**4.5. (O‑5 / Y‑05)** Спорные ситуации («мастер утверждает, что сдал продукцию, а данных нет») разрешаются совместной комиссией (мастер цеха, контролёр ОТК, инженер ПДО) на основе журнала аудита; корректировка — через Draft_AI после подтверждения; эскалация ≤ 15 мин.  
**4.6.** Шкала скидок: до 5% включительно — полномочие менеджера по продажам; свыше 5% до 10% — согласование директором; свыше 10% — не применяется.  
**4.7.** Второй подтверждающий для сумм > 100 000 ₽ — директор (Нагорный П.В.) либо уполномоченное лицо; SLA подтверждения — 1 рабочий день; отсутствие решения в срок оставляет документ в статусе ожидания подтверждения (проведение блокируется).  
**4.8.** Прайсы на металлопрокат предоставляются Заказчиком (Натхо Ю.Ч.) не позднее 5‑го рабочего числа месяца; до обновления действуют последние подтверждённые прайсы.  
**4.9.** Инвентаризация остатков сырья выполняется Заказчиком до приёмки MVP; результаты вносятся в собственную БД приложения.  
**4.10.** Подтверждение акта сдачи в ОТК контролёром ОТК входит в MVP (статусы п. 4.3 Приложения № 4).  
**4.11.** Переходный период: 14 календарных дней с даты ввода MVP допускается параллельное использование печатных форм.  
**4.12.** Регламент Базы знаний: исходные документы визируются ответственными (технолог — спецификации и нормы, экономист — ставки, администратор 1С — права доступа); векторизация — Исполнителем; обновление — не реже 1 раза в месяц.
