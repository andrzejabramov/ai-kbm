## 4. Статусы сущностей, целевые метрики (SLA) и принципы работы ИИ-агентов\*\*

> **4.1.** Статусы документа в приложении: Draft_AI (черновик создан AI) → Validated_by_User (подтверждён пользователем; для сумм > 100 000 ₽ — после двойного подтверждения) → Posted (проведён в собственной БД) → Synced_to_1C (для объектов интеграционного контура) → Archived; Draft_AI → Rejected → Draft_AI (повторная генерация). Запрещён прямой переход Draft_AI → Posted.

**4.2.** Статусы AI-сессии: Active; Escalated_to_Human (2 нераспознанных запроса подряд, SLA эскалации ≤ 15 мин); Closed.

**4.3.** Статусы передачи в ОТК: Pending_QC → QC_Approved → Archived; Pending_QC → QC_Rejected → Rework → Pending_QC.

**4.4.** Целевые метрики (SLA): время ответа AI p95 ≤ 5 с; точность извлечения сущностей ≥ 95% (расхождение > 5% → уточнение); доступность 99,5% в рабочие часы 08:00–18:00; время создания черновика ≤ 10 с; интеграция с 1С ≤ 30 с; уведомление об ошибке ≤ 5 с; деградация при недоступности 1С — режим «вопрос-ответ по базе знаний» с уведомлением пользователя.

**4.5.** Принципы работы ИИ-агентов: все документы — черновики Draft_AI, проведение только после подтверждения пользователем; подсветка полей с confidence < 80%; RAG-поиск только по векторной базе знаний (ChromaDB); запрет ответов «из головы»; двойное подтверждение сумм > 100 000 ₽; RLS — действия AI строго в правах авторизованного пользователя; полный аудит действий AI, срок хранения журнала 1 год; секреты (API-ключи, доступы) — только Docker Secrets/.env; защита от дублирующих запросов (хэш-проверка, блокировка 60 с).

**4.6.** Резервное копирование: ночные бэкапы PostgreSQL; RPO ≤ 24 ч; RTO ≤ 4 ч.
