### 2. ДОПОЛНЕНИЕ ПРИЛОЖЕНИЯ № 1 НОВЫМ РАЗДЕЛОМ

2.1. Дополнить Приложение № 1 к Договору новым разделом **«Раздел 13. Обеспечение безопасности чувствительных данных при работе с облачными моделями»** следующего содержания:

#### **Раздел 13. Обеспечение безопасности чувствительных данных при работе с облачными моделями**

**13.1. Общие положения**
13.1.1. Настоящий раздел определяет требования к обеспечению безопасности двух категорий чувствительных данных при их обработке с использованием облачных больших языковых моделей (LLM) и иных внешних сервисов:

- **Секреты** — API-ключи, токены доступа, пароли, приватные ключи, строки подключения к базам данных, сертификаты и иная конфиденциальная техническая информация.
- **Персональные данные (ПДн)** — любая информация, относящаяся к прямо или косвенно определённому физическому лицу, подлежащая защите в соответствии с Федеральным законом № 152-ФЗ «О персональных данных».

**13.2. Защита секретов (Secrets Management)**
13.2.1. **Инструменты управления секретами:**

- **SOPS (Secrets OPerationS)** от Mozilla: шифрование файлов секретов (YAML, JSON, ENV) с использованием KMS-ключей для хранения конфигураций в Git-репозитории.
- **HashiCorp Vault**: динамическая генерация, ротация и аудит доступа к секретам в продакшен-среде (Prod).
- **Docker Secrets**: безопасная передача секретов в контейнеры без монтирования в файловую систему.
- **.env + .gitignore**: локальное хранение переменных окружения для среды разработки (Dev).

  13.2.2. **Принципы работы с секретами:**

- Строгий запрет на хранение секретов в открытом виде в исходном коде (Git).
- Обязательное логирование всех операций доступа к секретам (кто, когда, какой секрет запросил).
- Разделение секретов по средам (Dev / Stage / Prod) с разными ключами шифрования и автоматической ротацией.

**13.3. Защита персональных данных (ПДн)**
13.3.1. **Метод обнаружения ПДн (комбинированный подход):**

- **Регулярные выражения (Regex)**: поиск структурированных паттернов (паспорт, ИНН, СНИЛС, телефоны, email) с точностью 95–98%.
- **NLP-модели (NER)**: распознавание именованных сущностей (ФИО, адреса) с использованием моделей для русского языка (например, Natasha) с точностью 90–95%.
- **Комбинированный пайплайн**: последовательное применение Regex → NLP → верификация контекста для достижения точности 98–99%.

  13.3.2. **Алгоритм обезличивания (токенизация):**

1. Детектор ПДн находит и классифицирует данные во входном запросе.
2. Токенизатор заменяет ПДн на псевдонимы (например, `CLIENT_001`, `PASS_001`, `INN_001`).
3. Обезличенный запрос передаётся в LLM для обработки.
4. Детокенизатор выполняет обратную замену псевдонимов на реальные данные после получения ответа от LLM.
5. Маппинг "псевдоним ↔ реальные данные" хранится в изолированной таблице PostgreSQL с применением RLS (Row-Level Security).

**13.4. Контроль и аудит**
13.4.1. Исполнитель обязуется проводить автоматическую проверку всех промптов, отправляемых в LLM, на наличие ПДн и секретов перед отправкой, а также вести журнал аудита всех операций с чувствительными данными сроком не менее 1 года.
